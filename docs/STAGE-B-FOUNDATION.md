# Подготовка этапа B: физический путь печати ещё не включён

Это намеренно ограниченная историческая контрольная точка разработки, а не заявление о завершении этапов A или B.

## Полученные аппаратные свидетельства

Последний отчёт владельца с подписанной сборки 0.1.0-a2.33 (22 октября 2026 года) подтверждает HONOR BRP-NX1, API 36, сборку BRP-N21 10.0.0.172(C636E6R4P1), ABI arm64-v8a, измеренный размер страницы памяти 4096 байт, USB Host=true и одно устройство: Canon LBP2900 VID:PID 04A9:2676. Разрешение Android на USB выдано. Интерфейс 0/альтернативная настройка 0 имеет класс 7/подкласс 1/протокол 2, OUT BULK 0x0001 и IN BULK 0x0082; однозначный выбор канала и захват без принуждения успешны. Корректный ответ `GetBasicStatus` был подтверждён ранее, последний отчёт содержит корректный 22-байтный ответ GetInputStatus. Полезная нагрузка состояния входа пока не интерпретируется; данные документа/страницы не отправлялись.

## Опорная версия исходного проекта

Публичный ValdikSS/captdriver, ветка `val`, коммит `892f320c019974a5b737e000fcc2c8582264a131`; изучены `src/capt-command.c/.h`, `generic-ops.c`, `prn_lbp2900.c` и `canon-lbp.drv`. Некоторые процедуры и комментарии смешивают пути протокола LBP2900 и LBP3000. Нельзя считать их профили команд взаимозаменяемыми. Кодирование команд, управление потоком, ответы и физические возможности требуют отдельной аппаратной проверки. Исходный проект использует GPLv3-or-later; **на этой контрольной точке его реализация не копировалась**, а последующий перенос нативного кода должен соблюдать требования к уведомлениям, лицензии и исходникам.

## Новые автономные подготовительные компоненты — только исходный код

- `core/CaptFrame`: ограниченное кодирование кадров и составных команд LE; длина ответа принимается как LE или BCD, только если результат в точности совпадает с числом полученных байтов. Вывод на принтер и автоматический повтор команд не реализованы.
- `core/BulkIo`: поддержка частичных чтений/записей с ограничениями, конечными сроками ожидания и явной неопределённостью частичной записи; скрытых повторов нет. `BulkChannel` — точка подстановки модульных тестов, а не подключённый к приложению транспорт Android.
- `core/JobSpecification`: проверка простых диапазонов, повторов страниц, границ исходника, копий и порядка с подборкой. Это логическая модель задания, а не проверенный профиль устройства.
- `core/JobLedger`: осторожный автомат состояний одного задания; при отключении во время передачи/подтверждения физический исход неизвестен, автоматического повтора нет.
- JVM-тесты проверяют независимо известные байты кадров, некорректные кадры, граничные случаи, частичные/неудачные операции USB, исключительное владение заданием и неоднозначный исход.
- Компоненты намеренно **не подключены к Activity**. Приложение на этом этапе ещё не печатает; реальную совместимость нельзя заявлять до обнаружения принтера и подтверждения доступа к правильному интерфейсу.

## Обновление аппаратной контрольной точки — 22 октября 2026 года

Владелец сообщил, что приложение обнаруживает ровно одно USB-устройство **04A9:2676** и разрешение Android выдано. Открытые USB-справочники сопоставляют этот ID с Canon LBP2900. На снимке нет раскрытого технического отчёта, поэтому класс/подкласс/протокол интерфейса, адреса/типы конечных точек и результат захвата ещё не подтверждены. Следующий шаг: использовать профиль точного ID только для распознавания в интерфейсе, затем проверить полный отчёт и добавить вручную запускаемый запрос состояния без записи, требующий единственной пары BULK IN/OUT и успешного захвата. Команды печати не включены.

## Добавлен запрос состояния CAPT без записи — 22 октября 2026 года; аппаратный результат ожидается

Интерфейс предлагает ручное действие **«Проверить состояние CAPT (без печати)»** только для точного VID:PID 04A9:2676 после получения разрешения USB. Отправляется только GetBasicStatus (0xE0A0) при единственной паре BULK IN/OUT, альтернативной настройке 0 и успешном захвате без принуждения. Ограниченный читатель ответа принимает длину LE или BCD только при совпадении с полученным кадром. Автоматический поиск по-прежнему не отправляет команд. Данные страницы, настройка задания, сброс принтера и команды печати не реализованы. Запрос требует физической проверки: синтетические модульные тесты не доказывают, что принтер отвечает.

## Подтверждённый базовый ответ и проверка расширенного состояния — 22 октября 2026 года

Владелец проверил подписанную сборку 20 на физическом Canon LBP2900. Отчёт подтверждает VID:PID `04A9:2676`, разрешение USB, класс 7/подкласс 1/протокол 2, OUT BULK `0x0001`, IN BULK `0x0082`, успешный захват и корректный шестибайтный GetBasicStatus с `statusFlags=0x88`, `secondaryFlags=0x00`. Открытый справочник CAPT определяет `0x88` как `ERROR_BIT|IM_DATA_BUSY`; этого недостаточно для вывода об одной конкретной аппаратной неисправности.

Ветка добавляет отдельное пользовательское действие `GetExtendedStatus` (`0xA0A8`) без записи. Требуются те же точное устройство, разрешение, однозначная BULK-пара и успешный захват. Парсер выдаёт заполненность буфера, вспомогательное состояние, флаги связи с движком, доступность бумаги и флаги движка. Команды очистки ошибки, сброса, настройки задания и страницы не отправляются. Модульные тесты покрывают декодер и парсер ответа; до слияния обязателен успешный CI PR. Физический ответ ExtendedStatus и физическая печать на этой контрольной точке ещё не проверены.

## Последние аппаратные данные и запрос GetPrinterInfo без записи — 22 октября 2026 года

- Получен GetInputStatus: кадр 22 байта, полезная нагрузка 18 байт. Поля намеренно не декодируются: изученный открытый путь captdriver запрашивает команду, но не определяет структуру её полезной нагрузки.
- Ветка добавляет GetPrinterInfo (0xA1A1) как ручную диагностическую операцию без записи. Парсер требует десять байт полезной нагрузки, прежде чем читать Blk по смещениям 6–7 и Buf по 8–9; при коротком ответе или нулевых значениях размеры по умолчанию не подставляются.
- Разбор GetExtendedStatus выдаёт Start/Printing/Shipped/Printed, только если присутствуют все четыре поля; иначе значения недоступны. PageReceived необязателен.
- Это по-прежнему подготовка диагностики. Инициализация задания, настройка страницы, передача растра HISCOA, StartPrint и физический путь печати в это изменение не входят.
