# R8 и APK для отдельных архитектур

Release включает R8, обфускацию и удаление неиспользуемых ресурсов. Правила
`app/proguard-rules.pro` сохраняют Java/JNI-мост LibreOffice, HISCOA, ограничения
worker и конструктор backend, создаваемого через reflection. Остальной код
не сохраняется общим правилом. Mapping сохраняется в артефактах CI.

Обычная `:app:assembleRelease` выпускает четыре самостоятельных APK с одним
applicationId, versionCode и постоянной подписью:

| Вариант | Суффикс имени в GitHub Releases | Состав нативных библиотек |
| --- | --- | --- |
| arm64-v8a | `-arm64-v8a.apk` | ARM 64 бит |
| armeabi-v7a | `-armeabi-v7a.apk` | ARM 32 бита |
| x86_64 | `-x86_64.apk` | x86 64 бита |
| universal | `.apk`, прежнее имя без ABI | Все три архитектуры |

Это полные APK, устанавливаемые обычным установщиком Android, не набор split
пакетов для `install-multiple`. Универсальный файл остаётся для старых версий
встроенного загрузчика и ручной установки. Документы, очередь и настройки при
обновлении поверх приложения сохраняются. Размеры измеряются после сборки,
обещания конкретного размера до измерения нет.

Новый загрузчик выбирает первую поддерживаемую архитектуру из
`Build.SUPPORTED_ABIS` в порядке Android. Отсутствие ABI-файла (HTTP 404)
разрешает запросить прежний универсальный файл. Сетевая ошибка, неверный
redirect или отказ проверки APK не разрешают скрывать ошибку таким переходом.
Если список архитектур не содержит известного ABI, запрашивается universal.
Правила HTTPS/доменов, проверка версии, пакета и подписи сохранены.

Схема `updates/android.json` остаётся прежней: её понимают уже установленные
клиенты. Публикатор перед объявлением версии проверяет каждый из четырёх APK:
подпись, метаданные, размер, SHA-256 из GitHub (если он предоставлен) и фактические
ABI/обязательные JNI-библиотеки. Неполный набор не объявляется. Исторический
релиз с одним universal продолжает приниматься. Публикация релизов и канала
остаётся только на доверенном main после проверок CI.

В CI универсальный debug-путь сохраняется через `-PsplitApks=false`. Отдельно
собираются и проверяются все четыре release APK. Полная оптимизация R8 требует
`debuggable=false`: отладочная сборка с одним `minifyEnabled` её не проверяет.
Поэтому `-Pr8Smoke=true :app:assembleRelease` создаёт отдельный, неотладочный
APK с тестовой подписью, суффиксом пакета `.debug` и синтетическим корпусом в
`r8-smoke-build/`. Постоянная подпись в этом режиме запрещена. Обычный release
не содержит этих Instrumentation и документов. На API 29/36 этот APK ставится
поверх debug и проверяет DOC/DOCX/XLS/XLSX, reflection backend, HISCOA и UI
обновлений уже после обфускации. Подписанный этап явно выбирает x86_64 APK для
эмулятора, проверяет обновление предыдущего релиза и переходы между universal и
APK устройства. Mapping и измерения сохраняются в артефактах.

Вручную проверить на ARM: установить предыдущий подписанный universal, обновить
поверх arm64-v8a или armeabi-v7a, открыть DOC/DOCX/XLS/XLSX, проверить предпросмотр
и печать, затем проверить выбор ABI в следующем встроенном обновлении.
Физическая печать Canon и поведение на ARM не подменяются проверкой эмулятора.
