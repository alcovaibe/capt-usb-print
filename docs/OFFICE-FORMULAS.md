# Формулы Excel: результаты и сохранённый кеш

LibreOffice не объявляется эквивалентом вычислителя Microsoft Excel. PDF должен
показывать результаты, а не исходный текст формул. Обычный корпус с правильными
сохранёнными значениями этого не доказывает: одинаковые 50/80 могут появиться
как после пересчёта, так и после чтения кеша.

## Воспроизводимая проба

`OfficeSyntheticFormulaCache` работает только с двумя точными SHA-256 встроенных
синтетических XLS/XLSX. Он изменяет сохранённые результаты D4/D6 с 50/80 на
−12345/−12346; выражения B4*C4 и SUM(D4:D5), исходные числа и оформление
не меняются. Исходные assets остаются неизменёнными. Для бинарного XLS заданы
смещения только данного закреплённого файла, после сверки SHA и исходных double.
Это не редактор/парсер произвольного пользовательского XLS.

Две дополнительные настоящие worker-конвертации выбирают первый лист без Fit.
Их PDF сохраняются тем же `copyForPrint`, что и остальные 16 доказательств.
Всего теперь 18 процессов/PDF. Каждый результат проходит admission, A4,
предпросмотр/диапазон/копии, HISCOA/spool без USB, проверку выхода процесса,
очистки и неизменности импортированного источника.

Poppler-контроль различает правильные 50/80 и подставленные сохранённые числа.
Промежуточное/неожиданное значение или вывод исходного выражения делают
проверку красной. В `office-formula-policy.json` записываются лишь фиксированные
метки `recalculated`/`saved_cache` для двух синтетических случаев. Содержимого
пользовательских книг там нет. Этот отчёт не создаётся пользовательским путём.

## Результаты и границы

Генератор обоих вариантов скомпилирован на host; оба файла прошли настоящую
проверку OfficeAdmission как XLS/XLSX. Настольный LibreOfficeDev 26.8 alpha
пересчитал XLS, но сохранил подставленные кеши XLSX. PDF первой страницы
обоих вариантов просмотрены: это результаты, не выражения формул.
Это отдельный настольный результат. Затем закреплённый Android LibreOffice
26.2.6.3 подтвердил то же различие на обеих API 29/36:
[Office CI 40188184469, код 6b674f6](https://github.com/alcovaibe/capt-usb-print/actions/runs/40188184469).
В обоих артефактах `office-formula-policy.json`: XLS — `recalculated`,
XLSX — `saved_cache`. Подставленные отрицательные значения видны в XLSX PDF;
это не вычисленные правильные 50/80. Предупреждение об устаревшем кеше
обязательно сохраняется перед печатью.

Проверяются только умножение и SUM в одной небольшой книге. Нельзя переносить
результат на все функции, ошибки, режимы пересчёта, пользовательские функции,
циклы, volatile-формулы или все импортёры. Макросы не выполняются, внешние
связи в принимаемом подмножестве отклоняются; они не используются для пересчёта.

Перед передачей в очередь внутренний экран явно предупреждает: результаты
могут быть пересчитаны иначе **или остаться сохранёнными и устаревшими**.
Пользователь должен сверить значения в готовом предпросмотре. Предупреждение
нельзя снимать на основании успеха двух простых формул. Печать использует этот
же PDF и не пересчитывает книгу повторно. Пользовательский SAF/Share Office
ещё выключен. Физическая печать Canon LBP2900 этим не подтверждается.
