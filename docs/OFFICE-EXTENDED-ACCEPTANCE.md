# Крайний Fit, шрифты и расширенный корпус — продолжение PR №33

26 октября 2026 года. Выполняются пункты 2, 3 и 4 **списка оставшихся работ
из отчёта владельцу**: крайние случаи Excel, лицензии/шрифты, расширенные документы.
Это не перенумерация исходного ТЗ. Обычный SAF/Share остаётся отдельным этапом;
main, сеть/updater, CAPT/HISCOA и публикация выпуска этой работой не меняются.

## Фактическая проверка вписывания

JNI/UNO адаптер после установки A4/ScaleToPagesX=1/Y=0 получает настоящие
дескрипторы страниц через XRenderable того же открытого документа. Для каждого
выбранного листа проверяются SourceRange и CalcPageContentSize всех страниц. Изменение
интервала столбцов означает горизонтальную разбивку. Один чрезмерно широкий
столбец проверяется отдельно: ширина его области не должна превышать полезную
ширину A4 даже при минимальном масштабе 10%. При отсутствии доказуемой геометрии,
слишком большом количестве страниц или несовместимых областях возвращается
отдельная ошибка FIT_WIDTH_UNSUPPORTED **до экспорта и передачи в очередь**.

Ошибка предлагает выключить Fit и проверить обычную разбивку либо изменить
исходный документ. Ручные вертикальные разрывы/высота не сбрасываются. Ручной
горизонтальный разрыв может быть поглощён самим Calc в режиме вписывания;
тогда принимается только действительно одностраничная ширина. Если Calc его
сохраняет и разбивает ширину, возвращается отказ. Раздельные печатные области
с разными столбцами консервативно отклоняются: утверждать единую ширину нельзя.
Не производится скрытая обрезка или дополнительное сжатие PDF при печати.

Предпросмотр, независимая копия очереди и подготовка HISCOA по-прежнему читают
единственный готовый PDF. Выбор листов сохраняет исходный порядок.

Старый корпус и его 18 конвертаций сохранены. Добавлены ещё шесть генерируемых файлов и четыре независимых регрессионных документа TDF:

OfficeExtendedSmoke выполняет 30 попыток через production URI-import и настоящий
worker. Ожидаются отказы предельной ширины, одиночного столбца, неодинаковых
печатных областей и всей книги с ними. После отказа обязателен успешный следующий
документ, неизменность источника, отсутствие нового задания и очистка дерева.
Успешные результаты проверяют первую/последнюю страницы PRINT-предпросмотра,
HISCOA/spool и HELD-копию общей очереди. USB не активируется.

Poppler проверяет конечные PDF: пагинацию, повторяемые шапки/номера, края,
последнюю строку/выбранный порядок, результаты и ошибки формул. Координаты текста
не должны выходить за A4. Из fontspec PDF извлекаются **фактически применённые
шрифты латинских меток**, а не только запрошенные имена из Word. Отчёт
office-font-fallback-observed.json относится исключительно к синтетике.
Он не объявляет проверенными каждый глиф или все варианты замены шрифтов.

Дополнительно без изменения байтов взяты публичные документы из закреплённого
LibreOffice core: 1-table-1-page.docx, bordercolours.doc и cell-borders.xls/xlsx.
Их исходные пути, blob и SHA-256 закреплены в config/office-upstream-fixtures.json;
уведомления/MPL приложены к debug-корпусу. Это независимые регрессионные входы,
не частные документы владельца. Каждый проходит настоящий worker, предпросмотр,
HELD-копию и подготовку HISCOA. Всего расширенная проба содержит 30 попыток;
прежние 18 конвертаций не удаляются.

Независимые DOCX/XLSX выявили дополнительный дефект admission: обычные
параметры уровня Deflate (ZIP-флаги 1/2) ошибочно отклонялись. Они теперь
допускаются только для метода Deflate 8 согласно
[PKWARE APPNOTE 4.4.4](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT).
Для Stored и неизвестных методов ограничения сохранены. Все прежние CRC,
согласованность локального/центрального заголовка, лимиты, запрет шифрования
и неподдерживаемых флагов остаются. Host-suite содержит 97 проверок, в том
числе все четыре варианта уровня сжатия и отказ неверного метода.

## Воспроизведение

```bash
python tools/fetch-office-upstream-fixtures.py
python tools/generate-office-extended.py app/src/debug/assets/office-fixtures
python tools/check-office-fixtures.py --write-manifest
bash tools/check-office-admission.sh
python tools/check-office-probe-runner.py
# APK с закреплённым движком, как в office-native.yml:
bash tools/run-office-worker-smoke.sh extended
python tools/check-office-extended-pdfs.py office-extended-synthetic.tar office-extended-results.json
```

Генератор требует python-docx/Pillow/openpyxl и настольный LibreOffice для
экспорта настоящих старых форматов; Android-сборка использует закреплённые байты.
Временные PDF/PNG не включаются в APK. Проверки оформлений не являются
сравнением с Microsoft Office. Автоматические результаты записываются по
окончательному SHA в PR после завершения CI. Наличие кода теста не означает PASS.

## Пределы и аппаратная проверка

Поддерживаемое подмножество OfficeAdmission не расширяется молча: Strict OOXML,
макросы/вложения/связи, пароли и неподдерживаемые старые варианты отклоняются.
Сохранённые значения формул XLSX могут быть устаревшими; предупреждение остаётся.
Шрифтовый fallback может менять страницы. Прежние наблюдаемые RSS/диск не
становятся жёсткими общими квотами RAM/диска. Состав и условия см.
[OFFICE-LICENSES.md](OFFICE-LICENSES.md).

Canon LBP2900 остаётся непроверенным для Office: нужны Word/Excel, совпадение
предпросмотра, диапазоны/копии/порядок, широкие/длинные листы, отмена и продолжение
после бумаги. Новый корпус и эмуляторы этого не подтверждают. Публичное
пользовательское включение Office и аппаратная приёмка не объявляются выполненными.
