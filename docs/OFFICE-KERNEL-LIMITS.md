# Ограничения ядром ОС для рабочего процесса Office

Продолжение PR №33. Независимая библиотека `capt_office_limits` использует
`setrlimit` только в одноразовом процессе `:office`. Она не связана с HISCOA,
не меняет протокол CAPT, USB или очередь. Пользовательский Office всё ещё
выключен до завершения остальных защит и приёмки.

## Что ограничено

Перед копированием исходника/распаковкой ресурсов/созданием backend служба
понижает мягкий и жёсткий пределы своего процесса:

| Ресурс | Предел по умолчанию |
| --- | --- |
| `RLIMIT_FSIZE` | Один создаваемый файл до 64 МиБ |
| `RLIMIT_CPU` | 90 секунд суммарного CPU процесса; резервный жёсткий предел 91 секунда |
| `RLIMIT_AS` | Исходный VmSize плюс 1536 МиБ на 64-bit / 768 МиБ на 32-bit |

Более низкий унаследованный жёсткий предел не повышается; значение AS также
ограничено представимостью конечного лимита в ABI. Значения читаются
обратно после установки. Ошибка установки не разрешает запуск backend.
Процесс после любого исхода по-прежнему завершается; лимиты не переносятся
на следующее задание. Понижение жёстких лимитов необратимо для непривилегированного
процесса, поэтому установка в основном процессе недопустима. Это проверяется
и Kotlin-кодом по точному имени, и JNI по суффиксу процесса.

`SIGXCPU`/`SIGXFSZ` завершают весь рабочий процесс. Обработчик использует только
async-signal-safe write/exit: фиксированный маркер CPU/FILE в заранее открытом
приватном дескрипторе, без Java, выделения памяти, имени файла или текста
документа в журнале. Контроллер читает только этот короткий фиксированный
маркер и возвращает `CPU_LIMIT` либо `FILE_LIMIT`; при отсутствии достоверного
маркера сохраняется обычная ошибка падения. В любом случае PDF не публикуется.
Проверка выхода PID/очистка остаются прежними.

## Что эти пределы НЕ гарантируют

- `RLIMIT_AS` ограничивает адресное пространство, а не RSS. ART/аллокатор могут
  заранее резервировать большие области, а затем наполнять их RAM без нового
  роста VmSize. Поэтому это **не жёсткая квота физической памяти**; прежнее
  наблюдение RSS 768 МиБ остаётся обязательным.
- `RLIMIT_FSIZE` относится к одному файлу, а не сумме каталога. Прежние
  192 МиБ/8192 записей и резерв места контролируются отдельно наблюдением.
- Это не файловая песочница и не блокировка внешних ресурсов. Процесс пока
  использует тот же UID. Полный запрет внешних локальных ресурсов, аудит
  журналов ядра и настоящий стресс OOM остаются незавершёнными.
- Отказ mmap с ENOMEM в проверке не означает физическое исчерпание RAM.
- Перехват CPU/FILE улучшает фиксированную диагностику, но при аварии/отмене
  родителем или изменении обработчика самим ядром Office может остаться
  общий WORKER_CRASHED. Ограничения не заменяют внешний таймаут/завершение PID.

## Проверки

`bash tools/check-office-kernel-limits.sh` выполняет реальные ограничения в
отдельных дочерних Linux-процессах: файл останавливается на 4096 байтах,
цикл расхода CPU завершается маркером, mmap 64 МиБ отклоняется при малом
AS-резерве. Проверяется неизменность лимитов родителя. Проверка прошла локально;
это не Android-результат и не Office-конвертация.

`OfficeKernelLimitsSmoke` на Android API 29/36 проверяет запрет установки в
главном процессе, настоящие CPU/FILE-сигналы в `:office`, отказ адресного
выделения, фиксированные ошибки, очистку и успешный новый процесс после отказов.
Ограничения основного процесса сверяются до/после. Backend — тестовый, USB
не активируется. Настоящие четыре формата, Fit width и UI дополнительно
проверяются отдельным Office CI с теми же пределами по умолчанию.

На `6fb863b` [основной CI 40183861804](https://github.com/alcovaibe/capt-usb-print/actions/runs/40183861804)
успешен: сборка/lint/тесты и обе API 29/36; журналы содержат
`CAPT_OFFICE_KERNEL_LIMITS_PASSED`. Это проверка настоящих Android-лимитов
с тестовым backend, не измерение ресурсов LibreOffice и не физический OOM.
Результаты следующих коммитов нужно сверить с точным HEAD PR.
Новых разрешений и INTERNET нет. Физическая
печать Canon LBP2900 не проверяется этим блоком. main/слияние/релиз запрещены.

Первичный источник семантики RLIMIT:
[Linux man-pages, getrlimit(2)](https://man7.org/linux/man-pages/man2/getrlimit.2.html).
