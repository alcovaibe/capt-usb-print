# Доставка обновлений Android

Реализация перенесена из `alcovaibe/Bluetooth-disabler`, main `acd9d32f0be70a4ff42ab9a9f73347925d0b38fa`. Сохранены строгий JSON-парсер, политика интервалов/отложенных версий, отдельные HTTP-клиенты и проверки APK. Compose заменён родными Android Views, используемыми CAPT. Значок повторяет исходный path, толщину 2,6, размер 28 dp, прозрачный фон и область нажатия 56 dp. Закрепление справа внизу: 12 dp от правого края и 8 dp над системной панелью. Нижний отступ прокрутки позволяет добраться до содержимого за кнопкой. Панель действий имеет верхние углы 32 dp, отступы 24 dp, заголовок 20 sp и кнопки 16 sp.

## Пользовательский путь

В подписанном приложении главный экран проверяет обновления при возвращении не чаще раза в 24 часа, включая неудачные/отменённые попытки. Перевод часов назад сбрасывает отметку без нового запроса. Ручная кнопка обходится без суточного интервала, но имеет паузу 5 секунд и общую блокировку одновременной проверки. Автоматические ошибки не открывают диалог; ручные объясняют ошибку и предлагают повтор. «Позже» сохраняет versionCode; новая версия снова может появиться, ручная проверка показывает и отложенную.

Проверка метаданных отменяется при уходе с главного экрана. Загрузка, начатая явным нажатием, переживает паузу и поворот через удерживаемую сессию без ссылки на Activity. Фоновой службы обновления, таймеров ОС и уведомлений нет. После гибели процесса загрузка начинается заново. Неудачные/отменённые частичные файлы удаляются; завершённые файлы в приватном cache/updates старше суток удаляются при следующем создании сессии. Свежий APK сохраняется после передачи установщику, чтобы не обрывать его временное право чтения.

Загружается только точный APK текущего канала, до 100 МиБ, с ограничением перенаправлений на HTTPS-хосты файлов GitHub. Перед предложением установки и при каждом нажатии «Установить» проверяются пакет, versionCode/versionName/minSdk, совместимость Android, отсутствие debug-флага и совпадение текущих сертификатов установленного приложения. Ключи/ID/схема версий не меняются; ротация ключа автоматически не поддерживается. Окончательную криптографическую проверку и подтверждение установки выполняет Android. Если установка из этого источника запрещена, открываются настройки; после возврата нужно ещё раз нажать «Установить». Отказ/отмена не означает успешную установку.

Debug (`.debug`) не обращается к каналу: кнопка объясняет ограничение. Первую версию с этим механизмом нужно установить вручную из подписанного Releases, после этого новые сборки можно получать внутри приложения. Старые установленные версии без кода проверки не смогут обнаружить его самостоятельно.

## Статический канал без отдельного сайта

У CAPT нет сайта Bluetooth Disable. Фиксированный endpoint:

`https://raw.githubusercontent.com/alcovaibe/capt-usb-print/refs/heads/updates/updates/android.json`

Отдельная ветка `updates` содержит публичный JSON. Приложение не использует GitHub API и токены; принимает только HTTPS по фиксированному адресу без перенаправлений. GitHub Raw отдаёт JSON как `text/plain`, поэтому разрешены UTF-8 `text/plain` и `application/json`; содержимое всегда разбирается строгим JSON-парсером до 16 КиБ. HTML, неизвестные поля, дубликаты, некорректные числа/UTF-8/URL отклоняются. ETag действует только вместе с проверенным кешем текущей сессии. Понижение версии внутри сессии отклоняется. HTTPS и права владельца на ветку остаются частью доверия; это не отдельный криптографически подписанный протокол метаданных.

Схема 1: `platform=android`, `channel=experimental`, `applicationId=com.cryonum.captusbprint`, `release=null` либо поля versionCode, versionName, minSdk, releaseUrl, notes {ru,en}. Канал намеренно экспериментальный: нынешние Releases являются prerelease. Пока поддержана действующая серия `0.1.0-a2.N`, tag `v0.1.0-a2-signed.build.N`, файл `CAPT-USB-Print-0.1.0-a2-build-N.apk`, код `1000+N`. Смена серии требует согласованного изменения генератора/валидатора/тестов.

## Автоматическая публикация

Существующий `android.yml` сохраняет подпись, проверку предыдущей версии и обновления поверх на эмуляторе, затем публикует APK. Новый `update-feed.yml` запускается после успешного завершения этого workflow на main. Выполняется только код доверенного main; файлы/артефакты PR не исполняются, секрет подписи не используется. Можно вручную повторить **Publish verified Android update feed** на main, если предыдущая публикация метаданных не удалась.

`tools/update-feed.py` выбирает максимальный номер опубликованного подписанного prerelease, требует успешный доверенный workflow для коммита тега, скачивает настоящий APK, проверяет apksigner по закреплённому публичному сертификату и читает пакет/версии/minSdk/debug через aapt. Проверяются имя/число/состояние/размер вложений и digest при наличии. После проверки релиз/вложения/коммит тега считываются ещё раз. JSON объявляет только реально опубликованный APK, без выдуманных метаданных или обещаний аппаратной печати.

Первая успешная публикация сама создаёт ветку updates от доверенного main; main не изменяется. Генератор сохраняет более высокий код и отклоняет конфликт одного кода. Только настоящий HTTP 404 означает отсутствие ветки/файла; проблемы доступа/сети не сбрасывают канал. Обновление файла использует SHA как защиту от конкурентной записи; workflow имеет очередь без отмены. До первого запуска после слияния endpoint ещё не создан, ручная проверка сообщит об ошибке доступа. Создание PR не публикует релизы и не включает работающий endpoint.

## Сеть и приватность

INTERNET добавлен только для проверки и загрузки обновлений; REQUEST_INSTALL_PACKAGES — для системного установщика. Печать/предпросмотр/диагностика остаются локальными. Сетевой код не читает документы, очередь, отчёты, USB-идентификаторы или настройки принтера; не отправляет их, cookies, Authorization или аналитику. GitHub видит IP-адрес и обычные метаданные HTTPS-соединения. Разрешения общей памяти не добавлены. Отдельный неэкспортируемый FileProvider открывает только cache/updates и выдаёт установщику временное чтение.

## Проверки и пределы

- `python3 -m unittest discover -s tools -p test_update_feed.py` — офлайн-проверки публикации, идентичности APK и отсутствия понижения/конфликтов.
- `:app:testDebugUnitTest` — JSON/URL, TLS/редиректы/размеры, интервалы/отмена/отложенные версии, загрузка/очистка, идентичность APK.
- Обычные сборка, lint и эмулятор API 36 остаются в CI.

Локальный Python-набор и существующая проверка ручного экспорта прошли. Локальная Android-сборка заблокирована загрузкой Gradle из сети; результат полного CI нужно смотреть на окончательном HEAD PR. Успешная реальная публикация endpoint и обновление подписанного приложения через установщик требуют проверки после управляемого владельцем слияния. Аппаратная печать этими проверками не подтверждается.
