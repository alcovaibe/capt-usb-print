# Проверка контейнера Office до нативного движка

Продолжение PR №33 от 25 октября 2026 года. `OfficeAdmission` — ограниченный
проверяющий код, **не рендерер Word/Excel**. Отображение остаётся задачей
закреплённого LibreOffice. Пользовательское открытие Office пока выключено.

## Место в конвейере

`OfficeWorkerService` сначала получает приватную копию через прежний импортёр,
затем вызывает `OfficeAdmission.inspect` и сверяет фактически найденный формат
с неизменяемыми параметрами задания. Только после успеха создаётся backend,
распаковываются ресурсы и запускается JNI. Расширение и MIME не определяют
формат. Работа выполняется в потоке отдельного процесса `:office`, до USB
и общей очереди. Контроллер по-прежнему ограничивает время и завершает процесс
при отмене; проверка контейнера дополнительно опрашивает interrupt/отмену.

Ошибка имеет только фиксированный код, без пути, текста XML, имени потока,
исключения провайдера или вложенной причины:

| Код конвейера | Значение для будущего интерфейса |
| --- | --- |
| `PASSWORD_REQUIRED` | Документ зашифрован; ввод пароля пока не поддерживается |
| `CORRUPT_DOCUMENT` | Нарушена проверяемая структура контейнера/основного потока |
| `UNSUPPORTED_DOCUMENT` | Формат/вариант или содержимое пока не поддерживается |
| `DOCUMENT_LIMIT` | Превышен допустимый размер, число записей или сложность |
| `CANCELLED` | Подготовка отменена |

Пользовательские русские сообщения ещё нужно подключить вместе с приёмом
Office. Возврат этих кодов из внутреннего API не означает готовность интерфейса.

## DOCX/XLSX: проверяемая часть OPC/ZIP

- Проверяются конец архива, центральный каталог, локальные заголовки, имена,
  флаги, методы, интервалы данных и дескрипторы. Нет префикса, наложений,
  нескольких дисков, ZIP64 или неоднозначного второго представления архива.
- Разрешены Stored и Deflate с проверенными флагами. Все части фактически
  читаются с проверкой распакованного размера и CRC, без извлечения на диск.
  Лимит проверяется и по объявленным, и по прочитанным байтам.
- `[Content_Types].xml` и корневые relationships определяют основную часть;
  её тип и корневой XML-элемент должны соответствовать DOCX либо XLSX.
  Учитываются Override и Default типов, абсолютная ссылка на часть внутри ZIP.
- Все части `.xml`/`.rels` разбираются SAX с запретом DTD/внешних сущностей,
  ограничением глубины, числа элементов и атрибутов. Ошибки SAX не журналируются.
- Внутренние relationships разрешаются относительно исходной части и должны
  указывать на существующую часть пакета. Явные внешние relationships, включая
  обычные гиперссылки, **сейчас отклоняются**, а не молча теряются.
- Имена частей ограничены ASCII URI без percent-экранирования; запрещены
  обход пути, обратный слеш, дубликаты и совпадения без учёта регистра.
  Это сознательно узкое подмножество, не обещание приёма любого корректного OPC.
- Macro-enabled типы, VBA, ActiveX, вложенные объекты, символьные ссылки ZIP
  и Strict OOXML пока отклоняются как неподдерживаемые.

Запрет внешних relationships и DTD не заменяет политику нативного импортёра:
ссылки могут содержаться в полях документа, формулах и других конструкциях.
Полная блокировка доступа к внешним локальным файлам ещё не реализована.

## DOC/XLS: проверяемая часть CFB и заголовков Office

Для CFB v3/v4 (секторы 512/4096 байт) проверяются заголовок, FAT/DIFAT,
продолжение DIFAT, каталог/дерево владения, mini-FAT и цепочки всех потоков.
Циклы, повторное владение сектором, выход за файл, недостижимые занятые
объекты и занятые потерянные секторы отклоняются. Потоки читаются по цепочкам;
весь документ не копируется в массив памяти. Таблицы ограничены размером
исходника, каталог — числом записей. Это не полная семантическая проверка DOC/XLS.

Для DOC проверяются `WordDocument`, идентификатор FIB `0xA5EC`, поддерживаемый
`nFib` (Word 97–2007: C1/D9/101/10C/112), `fEncrypted` и наличие выбранного
`0Table`/`1Table`. DOT и более ранние варианты Word пока не принимаются.
Для XLS поддерживается контейнер с BIFF8 `Workbook`: BOF версии `0x0600`,
границы записей/EOF и `FilePass`. BIFF5 и поток `Book` пока неподдерживаемы.
Существование `FilePass` означает шифрование; защищённый от изменения лист
не следует путать с паролем на открытие.

CFB с `EncryptionInfo` + `EncryptedPackage` получает ошибку пароля, включая
зашифрованные DOCX/XLSX. Обнаруженные хранилища VBA/макросов отклоняются.
Защита `NEVER_EXECUTE` в самом движке остаётся обязательной: проверка имён
потоков не доказывает отсутствие всех возможных исполняемых конструкций.

## Действующие пределы

| Ресурс | Предел проверки |
| --- | ---: |
| Исходник | 64 МиБ |
| Сумма распакованных ZIP-частей / CFB-потоков | 128 МиБ |
| Одна часть/поток | 32 МиБ |
| ZIP-части / записи каталога CFB, включая пустые | 4096 |
| Отношение распакованного размера ZIP-части к сжатому | 200:1 |
| Одна XML-часть | 4 МиБ |
| Сохранённые Content Types и relationships вместе | 8 МиБ |
| XML: глубина / элементы / атрибуты на элемент | 128 / 200000 / 256 |
| Метаданные OPC: глубина / элементы / атрибуты | 32 / 20000 / 32 |
| Длина значения XML-атрибута | 8192 символа |

Эти пределы намеренно могут отклонять корректные большие/сложные документы.
Дополнительно действуют [бюджеты процесса](OFFICE-WORKER.md). Это ограничение
работы проверяющего кода, **не жёсткая квота памяти/CPU всего LibreOffice**.

## Воспроизводимость и границы доказательств

`bash tools/check-office-admission.sh` компилирует тот же Java-код и выполняет
72 проверки. `OfficeIntakeSmoke` повторяет этот набор на Android API 29/36:
четыре исходных файла с правильными и ложными расширениями; ZIP с data
descriptors/CRC; лимиты размера/числа/сжатия; XML/DTD; внешние relationships;
шифрование; циклы и наложения FAT/mini-FAT/каталога; обе версии CFB; продолжение
DIFAT более 109 FAT-секторов; отмена и interrupt. Временные файлы удаляются.

Отдельная debug-служба сохраняет производственную проверку входа, но
останавливается до создания JNI-backend: через настоящий Binder проверяются
все четыре формата, несовпадение вида и повреждённый файл, очистка и неизменность
очереди. Служба ошибок lifecycle явно пропускает admission только для своих
синтетических fault-байтов. Обе службы не экспортируются и отсутствуют в release.
Настоящий `OfficeWorkerSmoke` проходит новую проверку перед четырьмя
конвертациями LibreOffice на API 29/36.

На кодовом коммите `040fe946f60b77e26b80b61bf3ee70212e874dfa` проверки завершились
успешно:

- [Основной CI 40175498972](https://github.com/alcovaibe/capt-usb-print/actions/runs/40175498972):
  сборка/lint/JVM, проверка разрешений APK, host-наборы, API 29 и 36. Intake
  выполнил те же 72 проверки и Binder/очистку; lifecycle и прежние проверки
  PDF/изображений/PrintService/очереди/готовой раскладки тоже прошли.
- [Office CI 40175498960](https://github.com/alcovaibe/capt-usb-print/actions/runs/40175498960):
  закреплённые пакеты всех трёх ABI восстановлены из кеша прежней исходной
  сборки; на API 29/36 прошли 12 прежних экспортов и четыре настоящие конвертации
  через новый worker/admission в отдельных процессах. Проверены все A4-страницы PDF,
  PRINT-предпросмотр и первая HISCOA/spool-страница без USB.
- Локально прошли 72 admission-проверки, 21 бюджета процесса, 20 импортёра,
  целостность корпуса, ручной экспорт JSON, пять сценариев runner, Bash-синтаксис
  и `git diff --check`. Отдельная проба подтвердила, что регрессия DIFAT обнаруживает
  удаление защитного условия. Gradle локально не скачивается из-за сети;
  Android-сборка/lint/JVM получены именно из CI.

Первый общий Android-запуск `e481a12` обнаружил ошибку нового теста: запись NIO
выполнялась после установки interrupt и сама вызывала `ClosedByInterruptException`
до admission. Подготовка файла перенесена перед interrupt, проверка отмены
сохранена; исправленный набор прошёл на обеих API. Эти результаты подтверждают
проверяемое подмножество контейнеров, не совместимость со всеми файлами Office.

Для последующих коммитов нужен результат их точного HEAD в PR; приведённые
ссылки фиксируют конкретный проверенный код. Физическая печать Canon LBP2900
этим этапом не проверяется. CAPT/HISCOA, USB-блокировка, PrintService и правила
очереди не изменены.
