# Следующий этап Office в PR №33

После отказа владельца от собственного Office-ядра используется готовый
LibreOffice. В этом продолжении реализована граница готовой печатной раскладки
и добавлена сборочная проверка движка. **DOCX/DOC/XLS/XLSX ещё не открываются
в пользовательском интерфейсе CAPT.**

## Что сделано

- `DocumentInspector.openPreparedPdf` принимает результат будущего конвертера
  из приватного каталога приложения, создаёт ограниченную независимую копию и
  проверяет размер каждой страницы. Не-A4, повреждённый PDF или отменённая
  подготовка не публикуются как готовый документ.
- `PreparedPdfLayout` фиксирует книжную/альбомную ориентацию каждой страницы.
  Смешанные разделы больше не обязаны получать одну ориентацию задания.
- `JobSpecification.preparedPdf` применяет существующие диапазоны и копии
  к одному результату. Карта ориентаций и выбор страниц неизменяемы.
- `DocumentSession` использует прежнюю геометрию готового A4 из системного пути:
  600/72 точек на пиксель и поворот в книжную сетку CAPT. Дополнительных полей
  260 px и APP_FIT для такого документа нет. Предпросмотр получает те же
  монохромные PRINT-полосы. Старый пилот FIT для готового PDF запрещён.
- Очередь проверяет согласованность плана и источника, владеет отдельной копией
  того же PDF и готовит полосы с ориентацией конкретной страницы. При сохранении
  приостановленного задания карта ориентаций попадает в приватный resume.json.
  Возобновление использует прежние подготовленные полосы, без повторной вёрстки.
- Старые прямые PDF/изображения и системный ANDROID_PDF сохраняют свою геометрию.
  Протокол CAPT, USB-движок и исходники HISCOA не изменены.

Этот внутренний API пока не соединён с DocumentActivity: сначала нужен
работающий, ограниченный Office-конвертер. Расширения/MIME Office не включены.

## Готовый движок из исходников

`config/office/libreoffice.json` закрепляет upstream LibreOffice 26.2.6.3,
коммит `8221e31b3ac356a1623c672912a3d2b492f7e3d1` и NDK 29.0.14206865.
Коммит соответствует [upstream-тегу](https://github.com/LibreOffice/core/tree/8221e31b3ac356a1623c672912a3d2b492f7e3d1)
и [опубликованной сборке F-Droid x86_64](https://f-droid.org/repo/org.documentfoundation.libreoffice_129.log.gz).
Это готовый сторонний движок, а не собственная реализация форматов.

Отдельный `office-native.yml` собирает arm64-v8a, armeabi-v7a и x86_64 на
обычных исполнителях GitHub. Упаковываются ядро/NSS/JNI-библиотеки, assets,
Java bootstrap, изменение исходника и корневые COPYING. Инвентаризация проверяет
архитектуру ELF и точку входа LOK, записывает размеры и SHA-256 файлов.
Успешные архивы кешируются по ABI и содержимому lock/сборочных скриптов, чтобы
исправления Kotlin/документации не требовали повторной сборки того же ядра.
Успешная сборка ещё не подтверждает загрузку/рендеринг ядра на Android.

После сборки всех ABI конвейер собирает отдельный отладочный вариант с
`-PofficeEngineDir=...` и запускает JNI-пробу на API 29/36. Она открывает только
четыре жёстко заданных синтетических файла из assets, проверяет тип документа
и имена трёх листов книги, экспортирует PDF и передаёт его в `openPreparedPdf`.
Подключение библиотек, bootstrap и ресурсов включается исключительно этой
сборочной опцией для debug. Обычная сборка/релиз не включает ядро. Эта проба
не принимает URI пользователя и пока не является производственным конвертером.

Upstream Viewer в этой версии использует SDK 35; он строится только как
промежуточный сборочный продукт. CAPT сохраняет minSdk 29 и compileSdk/targetSdk 36.
Нативный NDK готового ядра независим от закреплённого NDK 27.2 для HISCOA.
Архив не загружается приложением из сети, не включён в обычный CAPT APK и
не публикуется как релиз.

Применяется узкая проверяемая правка загрузки LibreOffice:
MacroExecutionMode всегда NEVER_EXECUTE независимо от параметров, а
UpdateDocMode — NO_UPDATE. Патч проверен на точном тексте upstream. Он
**не является полной блокировкой внешних ресурсов**: прямые ссылки на изображения,
локальные файлы и поведение конкретных импортёров ещё нуждаются в изоляции и
тестах. Отсутствие INTERNET в CAPT не запрещает чтение локальных ссылок.
Корневые COPYING также не заменяют полный лицензионный аудит состава ядра,
шрифтов и всех зависимостей перед включением в распространяемый APK.

## Проверки этого продолжения

| Проверка | Что она доказывает |
| --- | --- |
| `PreparedPdfLayoutTest` | A4/не-A4, смешанные ориентации, диапазоны/копии, неизменяемость, восстановление и отказ неполных/лишних метаданных; прежние планы не получают новые правила. |
| `PreparedPdfSmoke`, API 29/36 | Реальный Android PDF → PRINT-полосы → предпросмотр и HISCOA/spool без USB. Известные координаты меток выявляют повторный FIT/отступ; все пиксели предпросмотра сверяются с полосами. |
| Тот же Android smoke | Замена выходного файла конвертера не меняет готовый снимок; копия очереди побайтно совпадает с готовым PDF и переживает закрытие предпросмотра. Ошибка/отмена/поздняя не-A4 страница не оставляют новую приватную копию. |
| Прежние C/D smoke и JVM-тесты | Регрессии обычной печатной основы; не физическая печать. |
| `office-native.yml` | Сборка конкретного upstream для каждой ABI и состав файлов. Не конвертация и не исполнение в Android. |
| `OfficeEngineSmoke`, отдельная сборочная опция | JNI-загрузка и DOCX/DOC/XLS/XLSX → PDF на синтетическом корпусе, если задания API 29/36 завершились успешно. Не доказывает изоляцию, отмену, работу внешних ресурсов или физическую печать. |

Фактические результаты запусков фиксируются в описании PR с SHA и ссылками
на CI. Пока соответствующий запуск не завершён успешно, наличие теста или
конвейера нельзя считать пройденной проверкой.

## Что требуется дальше по исходному ТЗ

1. Довести сборку готового ядра и проверить JNI-загрузку в отдельном процессе
   на API 29/36. Зафиксировать полный состав лицензий, ресурсы и шрифты.
2. Реализовать отменяемую изолированную конвертацию всех четырёх форматов,
   ограничения времени/RSS/диска/распаковки и запрет внешних ресурсов.
   Ошибки пароля/повреждения/неподдерживаемого варианта должны возникать до USB.
3. Получать листы XLS/XLSX от движка, сохранять исходный порядок выбранного
   подмножества и менять Fit width без ограничения одной страницей по высоте.
   После каждого изменения создавать новую версию готового PDF и отбрасывать
   результат старой подготовки.
4. Подключить результат к готовому API из этой работы и DocumentActivity;
   исключить ручной повторный FIT/поворот, показывать замены шрифтов и ограничения
   формул до печати. Только затем включать Office в SAF/ACTION_SEND с проверкой
   настоящего содержимого.
5. Выполнить проверки реальной Office-конвертации на корпусе и дополнительных
   документах. Сравнить с Microsoft Office, где нужны заявления о совместимости.
   Аппаратно проверить Canon LBP2900, включая точный порядок листов, отмену и
   продолжение после бумаги. До этого поддержку нельзя объявлять принятой.

Слияние PR и выпуск APK этой работой не разрешены и не выполняются.
