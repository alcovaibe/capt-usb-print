# Вписывание Excel по ширине через LibreOffice

Продолжение PR №33 после `66219b1`. Добавлен внутренний экспериментальный
режим для XLS/XLSX. Пользовательский SAF/Share ещё выключен: внешние ресурсы,
жёсткие квоты, интерфейс и лицензионный аудит остаются отдельными этапами.

## Где задаётся раскладка

Android-обёртка закреплённого LibreOffice не предоставляет запись свойств
страницы Calc. Добавлен узкий синхронный JNI-адаптер
`Document.configureCalcFitWidth(int[])`. Его исходник
`tools/office/capt-calc-layout.hxx` включается в `desktop/source/lib/init.cxx`
при воспроизводимой сборке закреплённого ядра. Это использование UNO готового
движка, не собственный рендерер и не изменение CAPT/HISCOA.

До экспорта PDF адаптер получает стили страниц выбранных листов и задаёт:

- A4 210 × 297 мм либо 297 × 210 мм согласно исходному `IsLandscape`;
- `ScaleToPagesX = 1`;
- `ScaleToPagesY = 0`, то есть без ограничения высоты количеством страниц.

Исходные поля, колонтитулы, области печати и оформление ячеек не переписываются.
Поля проверяются: отрицательные поля или отсутствие места внутри A4 дают отказ.
Стиль, общий для нескольких выбранных листов, меняется один раз. Имена стилей
не выходят из нативного кода. После записи читаются размеры и параметры
масштаба; при несовпадении результат не экспортируется.

В закреплённом `ScStyleObj` запись ScaleToPagesX/Y сама очищает конкурирующие
параметры масштаба. Их значения из пула по умолчанию — 100 процентов и 0 общих
страниц; `ScPrintFunc` отдаёт приоритет активному масштабу по ширине/высоте.
Нельзя проверять здесь `PageScale == 0`: после очистки свойство возвращает 100.

Используется SolarMutex, без асинхронных `.uno:`-команд, диалогов, сохранения
промежуточной книги или её повторного импорта. Пустой массив означает все листы;
выбранные индексы проверяются на границы, дубликаты и исходный порядок книги.
Вписывание для DOC/DOCX отклоняется при создании параметров задания.

## Один результат для предпросмотра и очереди

Backend применяет свойства один раз к загруженной приватной книге, затем
экспортирует один PDF с тем же `SheetRange` и `SinglePageSheets=false`.
Далее работает прежний `openPreparedPdf`: проверка всех A4-страниц и независимая
готовая копия. Предпросмотр и очередь используют её без повторного FIT/полей.

Новый выбор листов или выключение вписывания требует нового задания из
неизменённого исходника в новом процессе. Мутация стилей не переходит в следующее
задание. Исходный пользовательский файл не сохраняется и не перезаписывается.
В режиме без вписывания сохраняется печатная раскладка исходника, включая
масштаб; результат по-прежнему должен соответствовать профилю A4.

## Проверки и статус

- Локально прошли прежние 72 проверки admission, 21 бюджета процесса,
  20 импортёра и целостность синтетического корпуса. Проверены применение
  патча к точному upstream, Python/Bash-синтаксис и `git diff --check`.
  Это ещё не доказательство нативной компиляции или работы раскладки.
- `OfficeOptionsTest` проверяет отказ Fit width для Word.
- Нативная инвентаризация каждого ABI теперь требует экспорт JNI-адаптера.
  Изменение входов сборки меняет ключ кеша: старый пакет без функции не подойдёт.
- `OfficeWorkerSmoke` расширен до 16 отдельных процессов: прежние четыре
  конвертации; для каждого XLS/XLSX три одиночных листа с вписыванием, все листы,
  подмножество 1+3 после выбора 3→1 и новое задание без вписывания.
- Широкий лист при 100% занимает 3 страницы, с вписыванием должен занимать 1;
  длинный должен оставаться многостраничным. Проверяются сумма страниц,
  независимый готовый PDF после выхода PID/очистки, первая/последняя страницы
  PRINT-предпросмотра, диапазон/копии и первая HISCOA/spool-страница без USB.
  Копия синтетического исходника сверяется после каждого задания.

Наличие проверок не считается их прохождением. Новая исходная сборка всех
трёх ABI и пробы Android API 29/36 должны быть подтверждены по точному HEAD
в PR. Gradle/Android SDK локально недоступны; Android-проверки выполняются в CI.
До успешного JNI-теста вписывание нельзя объявлять подтверждённым.

Остаются визуальная сверка оформления/правого края и результатов формул на
расширенном корпусе, интерфейс обновления предпросмотра и количества страниц,
предупреждения о шрифтах и другие ограничения из OFFICE-WORKER/ADMISSION.
Абсолютное совпадение с Microsoft Office не обещается. Физическая печать
нового режима на Canon LBP2900 не проверена; нужны широкая/длинная таблицы,
подмножество/все листы, диапазон/копии, отмена и продолжение после бумаги.
