# Office: отдельный рабочий процесс

Последующее продолжение пункта 1 — [файловый брокер/TSYNC и журналы](OFFICE-SANDBOX.md).
По новому указанию владельца сеть и updater сохранены как в main;
описание отсутствия INTERNET ниже относится к исторической точке.
Результаты Android CI защиты проверяются по текущей вершине PR №33.

Продолжение PR №33 от `4871f80`, 25 октября 2026 года. Это внутренний
экспериментальный конвейер. Открытие пользовательских DOCX/DOC/XLS/XLSX через
SAF/«Поделиться» по-прежнему выключено. Весь исходный запрос ещё не выполнен.

Продолжение очистки: `OfficePrivateFiles` удаляет принадлежащее запросу дерево
через `walkFileTree` без FOLLOW_LINKS, после остановки worker/читателей.
Символическая ссылка удаляется сама, её внешний объект не обходится. Это
аккуратная очистка известных приватных корней, не защита от произвольного
злоумышленника с тем же UID и не файловая песочница.

Результат удаления больше не игнорируется: отказ закрытия рабочего каталога
возвращает RESOURCE_OBSERVATION. Если к этому моменту уже создан независимый
PDF, он закрывается и не публикуется. Осиротевшие Office-каталоги при старте
главного процесса очищаются тем же способом; детский процесс их не трогает.
Невозможность удалить файлы не выдаётся за успешную очистку.

Host-проверка выполнила восемь проверок настоящих файлов/ссылок, включая
ссылку на внешний каталог, файл, отсутствующую цель и ссылку в корне.
Android lifecycle smoke дополнен реальным режимом 0500 рабочего каталога:
готовый PDF читается, удаление запрещено; ожидаются фиксированная ошибка,
отсутствие нового PDF предпросмотра, восстановление прав только тестом,
удаление остатка и успешное следующее задание. API-результат проверить по HEAD.

## Реализация

После callback выполняется дополнительная проверка времени/диска. После
подтверждённой остановки процесса размер/число файлов/резерв проверяются
снова, уже без фоновых записей движка. Превышение отказывает в публикации
и удаляет workspace. Android fault backend проверяет быстрый результат:
2 МиБ записаны при бюджете 1 МиБ, пока наблюдатель намеренно задержан между
замерами; завершение конвертации не должно обходить предел. Это финальная
проверка результата, а не жёсткая суммарная дисковая квота во время записи.
RSS также повторно наблюдается после callback, до остановки. Второй быстрый
fault удерживает дополнительные 96 МиБ реально затронутых страниц RAM при
бюджете RSS успешного малого worker +32 МиБ; он должен получить MEMORY_LIMIT, пока
наблюдатель задержан. Это ограниченный тест удерживаемой памяти, не физический
OOM и не гарантия обнаружения краткого пика, освобождённого между замерами.

`OfficeWorkerClient.prepare` вызывается вне главного потока и принимает
приватный файл, формат и неизменяемый выбор листов. Одна конвертация занимает
один слот; конкурентный запрос получает `BUSY`. Это ограничение конвертера,
а не новая очередь печати.

Исходник передаётся через Binder дескриптором только для чтения. Имя файла,
URI и текст исключения поставщика не входят в протокол и сообщения об ошибках.
Каждый запрос имеет приватный каталог с UUID. Служба копирует ограниченный
исходник, запускает LibreOffice и возвращает PDF и имена листов в приватной
памяти. Содержимое и имена листов не записываются в JSON/журналы приложения.

Один процесс `:office` выполняет ровно одно задание. Контроллер проверяет UID,
имя и PID процесса, запоминает время его создания из `/proc/PID/stat` и перед
завершением сверяет его снова. Главный процесс не завершается; PID после
смерти Binder повторно не используется. Успех, ошибка, отмена и таймаут
заканчиваются отвязкой службы и завершением рабочего процесса. До публикации
результата контроллер ждёт его смерти; нативный движок повторно не используется.

Отмена не зависит от отзывчивости нативного кода. При неудачной остановке
результат не публикуется и рабочий каталог не удаляется из-под живого процесса.
Смерть Binder сама по себе не считается выходом Linux-процесса: проверяются
его идентичность и ответ ядра `ESRCH` на проверку существования PID. Неизвестное
состояние не выдаётся за остановку. Android-тесты независимо проверяют выход
каждого рабочего PID через API ядра.
Осиротевшие каталоги очищаются при новом главном процессе; автоматического
возобновления конвертации нет. `CaptApplication` дочернего процесса не запускает
очередь/USB и не удаляет живые копии предпросмотра главного процесса.

После остановки `DocumentInspector.openPreparedPdf` создаёт независимый снимок,
проверяет каждую A4-страницу и фиксирует ориентации. Только этот `DocumentSession`
становится готовым результатом; исходник, профиль, кеши и PDF конвертера
удаляются. Предпросмотр и прежний API общей очереди используют готовый снимок,
без второй вёрстки. Повреждённый PDF и не-A4 отклоняются до очереди/USB.

Выбор XLS/XLSX сортируется по порядку книги, копируется и защищается от
изменений. Пустой набор, дубликаты и недопустимые индексы отклоняются. Backend
проверяет индексы по настоящему числу листов и использует штатный `SheetRange`
PDF-фильтра. `SinglePageSheets=false` сохраняет страницы по высоте.
**Fit width ещё не реализован:** запрос явно возвращает `UNSUPPORTED_LAYOUT`,
а не игнорирует настройку.

## Ресурсы и границы гарантий

| Ограничение | Значение |
| --- | --- |
| Исходник | 64 МиБ, потоковое приватное копирование с буфером 64 КиБ. |
| PDF | 64 МиБ, до 1000 A4-страниц. |
| Время | 120 секунд на привязку/конвертацию; остановка/отвязка дополнительно ожидаются до 2 + 2 секунд. |
| Память процесса | Наблюдаемый RSS до 768 МиБ; именно `VmRSS`, не размер Java-кучи или кешированный PSS. |
| Рабочие файлы | Наблюдаемый объём до 192 МиБ, до 8192 записей вместе с каталогами; без символических ссылок и специальных файлов. |
| Свободное место | Резерв 8 МиБ до и во время работы. |

Время/RSS/дерево проверяются примерно каждые 100 мс. Недоступный или некорректный
RSS вызывает фиксированную ошибку; неизвестный расход не подменяется нулём.
Первая выборка RSS и проверка лимита выполняются до передачи исходника backend:
даже очень быстрая конвертация не может обойти начальную проверку памяти.
При исчезновении процесса есть ограниченное ожидание доставки Binder death.
Дерево обходится без следования по ссылкам и хранения всех путей в памяти;
исчезнувший временный файл допускается как гонка с удалением движком.

**Это наблюдение, не жёсткая квота ОС.** Между выборками возможен выход за
порог; обход дерева/локальный ввод-вывод тоже занимают время. Не реализованы
ограничение адресного пространства/CPU ядром, общий бюджет распаковки OPC/ZIP
и ресурсная изоляция импортёра. Проверка низкого порога RSS не является
настоящим OOM. Снимок PDF и будущий spool отдельно подчиняются существующим
лимитам импортёра и очереди.

`:office` работает **с тем же UID**. Это не песочница ОС и не запрет чтения
внешней локальной ссылки. INTERNET отсутствует, `NEVER_EXECUTE`/`NO_UPDATE`
сохранены, но полной блокировки внешних ресурсов пока нет.

Просто включить `android:isolatedProcess=true` нельзя: Android запрещает
изолированной службе открывать приватные файлы приложения, хотя разрешает
использовать уже переданные дескрипторы. Нынешний порт LibreOffice создаёт
профиль/временные файлы и открывает ресурсы по путям. Нужна адаптация файлового
доступа либо проверенная политика движка. Источники:
[описание службы](https://developer.android.com/guide/topics/manifest/service-element)
и [политика isolated_app](https://android.googlesource.com/platform/system/sepolicy/+/23c9d91b46352bd91cdc58f33d55378e5567dc1c/private/isolated_app.te).

Новый backend отключает перенаправление stdout/stderr в logcat. Это не полный
аудит прямых диагностических записей upstream. Пользовательские документы
нельзя подключать до проверки внешних ресурсов и всех журналов ядра.

Поэтому реальная служба и backend регистрируются только в opt-in debug с
`-PofficeEngineDir`. В обычных debug/release активного Office-конвертера нет.
SAF/Share не расширены. Тестовая служба ошибок — только debug, не экспортируется
и не является обработчиком Office-форматов.

## Воспроизводимые проверки

- `bash tools/check-office-work-budget.sh`: 21 host-проверка границ времени,
  RSS/переполнения, диска/числа записей, свободного места и символических ссылок.
- `OfficeOptionsTest`: неизменяемость и порядок листов, отказ пустого набора,
  дубликатов/недопустимых индексов и выбора листов для Word.
- `OfficeWorkerLifecycleSmoke`, обычные API 29/36: настоящие процессы,
  тестовый backend. Успех и независимая готовая копия; отмена до старта и во
  время работы; interrupt; зависание/таймаут; смерть процесса; пороги RSS/диска;
  резерв свободного места; ошибка движка без приватного текста; повреждённый и не-A4 результат; очистка
  и следующее задание после отказов. Это не Office-вёрстка и не настоящий OOM.
- `OfficeWorkerSmoke`, opt-in API 29/36: четыре настоящих формата через
  Binder/LibreOffice в разных процессах. DOCX/DOC — по 3 страницы; листы 1+3
  XLS/XLSX — по 7. Проверяются имена листов, готовый PDF после удаления рабочего
  каталога, PRINT-предпросмотр, диапазон/копии и первая HISCOA/spool-страница.
  В синтетическом отчёте — наблюдаемый пик RSS, не точный максимум между выборками.
- Прежние 12 экспортов `OfficeEngineSmoke` и проверки PDF/изображений,
  PrintService/очереди/готовой раскладки сохранены.

Результаты сверяются по точному HEAD в PR; наличие теста не считается успехом.
Gradle локально ограничен сетью. Физическая печать Office на Canon LBP2900
не проверена. Аппаратный план остаётся в OFFICE-FIXTURES.md.

До пользовательского включения остаются: внешние ресурсы и журналы ядра;
жёсткие бюджеты и OPC/CFB/пароли; Fit width; предупреждения о шрифтах/формулах;
интерфейс приёма/листов; лицензии/шрифты и аппаратная приёмка. CAPT, нативный
HISCOA, USB-движки и правила очереди не изменены. Слияние и релиз не выполняются.

## Первая проверенная версия рабочего процесса

В [Office CI 40171548171](https://github.com/alcovaibe/capt-usb-print/actions/runs/40171548171)
на `d476f09` настоящие конвертации в разных процессах успешны на API 29/36.
Отчёт API 29 содержит следующие наблюдаемые пики RSS:

| Формат | Страницы | Наблюдаемый пик RSS, байт |
| --- | ---: | ---: |
| DOCX | 3 | 285 196 288 |
| DOC | 3 | 244 621 312 |
| XLS, листы 1+3 | 7 | 240 607 232 |
| XLSX, листы 1+3 | 7 | 295 538 688 |

Это измерения только синтетического корпуса на эмуляторе, не гарантия памяти
для любых файлов/устройств. API 36 lifecycle в первом запуске успешен; API 29
обнаружил гонку теста с `Application.onCreate`. Перед созданием контрольного
файла добавлен `waitForIdleSync`. Окончательные результаты нового HEAD должны
быть сверены в PR; старый зелёный Office CI не заменяет проверку этого изменения.

## Проверка входа перед backend

После `7975203` подключён [OfficeAdmission](OFFICE-ADMISSION.md): проверка
содержимого OPC/CFB, ограничение распакованных байтов и отдельные ошибки пароля,
повреждения/неподдерживаемого варианта. Она выполняется до `newBackend`/JNI.
Предыдущие упоминания отсутствия OPC/CFB/распаковочных ограничений выше относятся
к первой версии процесса. Полная файловая изоляция и жёсткие квоты всего движка
по-прежнему не реализованы; ограничения admission их не заменяют.

## Экспериментальное вписывание Excel

После `66219b1` режим Fit width передаётся в нативный UNO-адаптер, вместо
безусловного UNSUPPORTED_LAYOUT. Подробности и необходимость новой проверки
ядра всех ABI/API — в [OFFICE-FIT-WIDTH.md](OFFICE-FIT-WIDTH.md). Прежние
упоминания отсутствия режима выше относятся к предыдущей версии.
