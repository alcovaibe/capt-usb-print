## Формат и поля

Полный Extended — **56 байт**, заголовок `A8 A0 38 00`: 4 байта заголовка и 52 байта нагрузки, длина LE `0x0038 = 56`, а не BCD 38. Рабочий читатель получил 6 и затем 50 байт; отсутствующего остатка здесь не видно.

| Абсолютное смещение в кадре, от нуля | Поле |
| --- | --- |
| 0–1 / 2–3 | Код операции LE / общая длина кадра |
| 4 / 5 | Extended Bas / Bas1; их нельзя менять местами |
| 8–9 | Уровень буфера, LE |
| 12 / 13 / 14 | Aux / Cnt / Pap |
| 16–17 | Eng, LE |
| 18–25 | Decoding, Printing, Out, Completed: четыре слова LE |
| 38–39 | Received: слово LE |

`A0 E0 06 00 88 00` — корректный для транспорта шестибайтный кадр с двумя байтами нагрузки. Это не доказывает соответствие первого байта нагрузки флагам полной структуры Basic. Extended Bas1 `88` также не является Extended Bas `88`. SetPowerDown `80 00` и Reserve `87`/`8C` — ответы разных команд с разными контрактами. Перестановка байтов, изменение границы заголовка и список разрешённых `88` не добавляются.

## Реализованное поведение

Все четыре движка (одностраничный тест, двухстраничный тест, одностраничный PDF-пилот и очередь документов, включая задания Android PrintService) используют общую политику допуска LBP2900:

1. GetPrinterInfo с проверкой ограничений передачи.
2. Опрос ExtendedStatus; обработка запрошенного InputStatus и перечитывание ExtendedStatus. Свидетельства ошибки движка/связи/состояния, недоступности бумаги и неполные счётчики отклоняются. Ожидающий Input, занятость/NOTREADY, выдача и разные счётчики ожидаются в прежнем бюджете 5 секунд / 21 выборка. Задержка транспорта добавляется отдельно; отмена проверяется перед каждым запросом.
3. Одна попытка ReserveUnit с собственным нулевым Error и ненулевым JobID.
4. Однократный SetPowerDown: проверяются формат и двухбайтная длина, слово ответа сохраняется без объявления принятия печати. Extended/Input проверяются повторно, включая ограниченное ожидание NOTREADY, **до JobInfo START**.
5. Прежняя условная последовательность офлайна, инициализации, онлайна и страниц. Обязательные управляющие ACK, точные счётчики, END и Release продолжают проверяться.

Так возвращается допуск Extended/Input исторически работающих Android-путей и порядок фаз закреплённой подготовки, но не точная последовательность её запросов состояния. В закреплённой версии `capt_get_xstatus` сначала читает Basic и обновляет Extended только по вторичному биту изменения. Подготовка не применяет прежний запрет допуска Basic `0x8e`. Свежий Extended здесь позволяет не полагаться на короткую структуру Basic или кешированные поля Extended. Заменён необоснованный дополнительный барьер Basic; `88` не подменяется готовностью. В диагностике без записи Basic сохраняется необработанным с SHORT_UNVERIFIED. OFFLINE/неизвестные начальные биты не стираются вымышленно. Бит FREE не превращён в новое обязательное условие: заметки описывают свободное онлайн-состояние без него, а владение авторитетно подтверждает ReserveUnit.

Намеренно сохранено ещё одно различие: исторически работавший Android `powerDownSettings()` отправляет `00 00`, а закреплённая подготовка C — `01 00` через `lbp6000_job_init`. Объясняет ли это ответ `80 00`, не доказано. Одновременное изменение настройки и правила допуска затруднило бы установление причины. Исправление сохраняет известный запрос Android, записывает ответ и проверяет следующее состояние. Оно не объявляет настройку принятой и не утверждает полное совпадение обмена с исходным драйвером. До изменения нагрузки нужен последующий захват официального драйвера с изменением одной переменной.

Error ReserveUnit теперь должен быть строго нулевым согласно таблице протокола. Закреплённый C `capt_reserve_unit` фактически проверяет только бит 0x80; прежнее утверждение о проверке полного нуля было неверно. Android намеренно строже: проверка только старшего бита могла бы принять ненулевой младший код ошибки с ненулевым JobID. Непонятный второй байт остаётся неинтерпретированным. Это исправление контракта с опорой на источники, а не заявление о таком младшем коде в отчётах владельца.

В трассу добавлены отдельная фаза CONFIGURING_JOB и powerDownResponseWord с printAcceptance=false. Ошибки настройки объясняют, что данные страницы не отправлены, сохраняя неопределённость жизненного цикла CAPT, где резервирование уже могло произойти. UNKNOWN объясняет наличие ответа принтера без подтверждённой готовности. Для следующей попытки пользователю не требуется интерпретировать HEX.

Автоматические Release неопределённого резервирования, сброс, опустошение/очистка конечной точки, повтор, выдуманный JobID и повтор задания не добавлялись. Прежняя обычная инициализация не является новым путём восстановления. Владение USB, точный читатель ответов, приватность исходников, подпись и только ручной экспорт сохраняются.

## Пределы проверок

Полученные образцы доказывают сохранение байтов и воспроизводят наблюдавшееся начало. Всё после полученного SetPowerDown в успешном тесте — явно **синтетическое продолжение**, включая последующее состояние, обязательные ACK, счётчики и физический вывод. Тесты покрывают аппаратные ошибки, неполные счётчики, повторные Input, ограниченную занятость/NOTREADY, отмену, отдельные Reserve `87`/`8C` и ненулевой младший Error с корректным JobID, отрицательные JobInfo/END/Release и отсутствие автоматического повтора.

Локальные проверки ручного экспорта и изменений прошли. Загрузка локального Gradle блокировалась сетью; CI последней ревизии PR должен собрать приложение, выполнить lint, JVM-тесты и существующие проверки системной печати/растра/диагностики/восстановления API 36. Успешный эмулятор всё равно не доказывает физическую печать LBP2900 или HONOR Documents. Слияние и выпуск остаются под управлением владельца.
