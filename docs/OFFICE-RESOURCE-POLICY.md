# Ресурсы Office: общий допуск, наблюдение и ограниченные стресс-проверки

Пункт 3 последнего аудита, продолжение PR №33 от `7b25051`.
Пользовательское подключение Office в обычную сборку/SAF/«Поделиться» остаётся
последним этапом. INTERNET сохраняется для проверки и скачивания обновлений APK;
документы/отчёты не передаются updater, сеть Office-worker закрыта.

## Общие проверки

Раньше наблюдались преимущественно RSS и дерево текущего worker. Теперь
OfficeResourceMonitor дополнительно считает вместе четыре приватных корня:
office-ui (исходники экранов), office-work (импорт/движок/PDF),
stage-c-inspection (предпросмотры) и print-queue (источники и подготовленные полосы).
Существующие не-Office документы в этих корнях тоже занимают место и учитываются;
их обычные пути печати не получают нового Office-допуска.

| Проверка | Правило |
| --- | --- |
| Совокупный объём четырёх корней | Не более 512 МиБ и 16384 записей; считаются логические длины файлов, обход без следования по ссылкам. |
| Свободное место | Минимальный запас 32 МиБ. До старта дополнительно требуется место на предполагаемый максимальный рост. |
| Импорт | Рост 384 МиБ: источник 64 + worker 192 + подготовленный PDF 64 + копия очереди 64. С запасом — 416 МиБ свободного места. |
| Преобразование/список листов | Рост 320 МиБ: worker 192 + PDF 64 + копия очереди 64. С запасом — 352 МиБ. Для списка это намеренно консервативно. |
| Перед копированием готового PDF | Требуется место на его фактическую длину, плюс запас; копирование проверяется по блокам. |
| Перед Office HELD-очередью | Фактическая длина PDF + 256 МиБ на подготовленные полосы, плюс запас. Прежняя общая квота очереди 256 МиБ сохранена; расчёт допуска консервативный. |
| Системная память | lowMemory=false; availMem не меньше threshold + 64 МиБ. Неизвестные/неправдоподобные значения не считаются успехом. |
| RSS worker | Не выше min(бюджета попытки, totalMem / 3); прежние пределы 256 МиБ импорта и 768 МиБ преобразования не повышаются. |
| RSS основного процесса + worker | Не выше min(1 ГиБ, totalMem / 2). Общие страницы могут считаться дважды: это консервативный допуск. |

Оценённый рост должен помещаться и в остаток общего лимита 512 МиБ.
Проверки выполняются перед началом и затем раз в 500 мс; прежний контроль
worker остаётся раз в 100 мс. Перед публикацией результата и после подтверждённого
выхода worker общий замер обязателен. Проверки продолжаются при копировании
готового PDF, подготовке предпросмотра и копировании Office в HELD-очередь.
Отмена проверяется в том числе при обходе каталогов. Неизменённые перегрузки
openPreparedPdf/enqueue сохраняют прежние контракты других форматов.

Это не резервирование блоков диска и не жёсткая суммарная квота ядра. Другие
процессы могут занять память/диск после проверки; короткий пик возможен между
замерами. RLIMIT_AS ограничивает адресное пространство, RLIMIT_FSIZE — один
файл; они не заменяют RSS/сумму дерева. Жёсткая RSS/проектная файловая квота
не предоставляется обычному приложению используемым здесь механизмом.

## Ошибки и приватность

OfficeWorkerProtocol просматривает максимум восемь типизированных причин:
ENOMEM/OutOfMemoryError → MEMORY_LIMIT, ENOSPC/EDQUOT → NO_SPACE,
EFBIG → FILE_LIMIT. Текст исключений не анализируется и не включается в UI/JSON.
Неопознанный крах не объявляется OOM без доказательства. Русское сообщение
памяти предлагает закрыть другие приложения или выбрать меньше листов.
Результат при отказе не публикуется; процесс завершается, исходник очереди
не создаётся либо неполная копия удаляется. Следующее задание проверяется отдельно.

## Что именно проверяется

- Host `check-office-work-budget.sh`: арифметика границ/переполнения, системная
  память/суммарный RSS, свободное место на рост, общий счётчик нескольких
  настоящих каталогов, отсутствующий корень, ссылки и отмена обхода.
- Host `check-office-kernel-limits.sh`: прежние CPU/FILE/AS и новая реальная
  запись страниц до ENOMEM в дочернем процессе с RLIMIT_AS; основной процесс
  сохраняет лимиты. Запись в /dev/full даёт настоящий ENOSPC без заполнения диска.
- Android `OfficeKernelLimitsSmoke`: новый одноразовый worker записывает
  анонимные страницы до ENOMEM, максимум 64 МиБ, освобождает их и получает
  MEMORY_LIMIT. Проверяются очистка, неизменность основного процесса и следующий
  успешный worker. Это реальный отказ выделения адресного пространства после
  физической записи страниц, а не глобальный OOM телефона.
- Android `OfficeResourceStressSmoke`: реальные небольшие файлы в разных
  приватных корнях; отказ допуска из-за суммы; недостающее место на будущий рост;
  инъецированный lowMemory до привязки и после начала worker; типизированные
  ENOSPC/EDQUOT/ENOMEM/EFBIG с приватными контрольными строками; проверенный выход
  PID, отсутствие новых заданий/утечек и следующий успешный PDF.
- Обычный и Office CI выполняют ресурсную пробу на API 29/36. Настоящий
  LibreOffice после отказов по-прежнему должен пройти прежние 18 конвертаций,
  внутренний UI и расширенные 30 попыток/проверки конечных PDF.

Системные lowMemory/errno в Android-пробе инъецируются явно. Полностью заполненный
диск, исчерпание всей RAM и срабатывание LMKD устройства не проверены и не
объявляются выполненными. Проверенный отказ mmap/host /dev/full их не заменяет.
Локальная Android-сборка блокируется загрузкой Gradle по сети; окончательные
результаты фиксируются по точному SHA в PR. Физическая Canon LBP2900 отдельно
не проверена; слияние и выпуск запрещены.

Основания семантики:
[ActivityManager.MemoryInfo](https://developer.android.com/reference/android/app/ActivityManager.MemoryInfo),
[память Android и low-memory killer](https://developer.android.com/topic/performance/memory-management),
[Linux getrlimit](https://man7.org/linux/man-pages/man2/getrlimit.2.html).
