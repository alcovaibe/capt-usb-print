## 25 октября 2026 — расследование красной JNI-пробы PR №33

Актуальный `main` остаётся `e41d209bea88e8e46d76f5cc30272d278b604aaa`;
продолжается отдельная ветка `prep/office-engine-intake`, обычный PR №33.
В запуске [40118651290](https://github.com/alcovaibe/capt-usb-print/actions/runs/40118651290)
сборка LibreOffice для всех трёх ABI прошла, а Android-пробы 29/36 упали.
Повтор [40168844282](https://github.com/alcovaibe/capt-usb-print/actions/runs/40168844282)
с сохранением logcat выявил `ClassNotFoundException: OfficeEngineSmoke` на API 29:
класс не включался в DEX, до JNI и конвертации дело не доходило.

Причина: в AGP 9 со встроенным Kotlin дополнительный каталог `.kt` нельзя
подключать через `AndroidSourceSet.java`. Он перенесён в
`AndroidSourceSet.kotlin`; Java/JNI-обёртки остаются в `java`.
Прежнее утверждение о компиляции Kotlin-пробы в обычном debug было неверным.
Успешный Android CI 164/165 проверял приложение и готовый PDF, но не этот класс.
Подтверждение исправления должно включать сборку нового HEAD, наличие класса
в DEX и запуск самого движка; одного исправления Gradle недостаточно.

Добавлены: стадия пробы и logcat/crash-buffer при любом исходе, таймаут процесса
и ограниченный сбор диагностики, очистка старых результатов перед запуском,
пять host-сценариев runner (включая crash с exit=0 и timeout). PDF-export теперь
проверяет настоящий `jint` saveAs, который upstream Java отбрасывал как `void`.
Ресурсы/профиль/fontconfig пробы принадлежат одному временному каталогу;
исходный путь fontconfig пакета Viewer заменяется перед инициализацией.
Эти изменения относятся только к синтетической debug-пробе. Они не являются
производственным изолированным конвертером и не включают Office в SAF/Share.

На `df8d287` [отдельный Office CI 40169364971](https://github.com/alcovaibe/capt-usb-print/actions/runs/40169364971)
полностью успешен: все ABI и реальная конвертация четырёх синтетических файлов
на API 29/36. На API 36 DOCX/DOC дают по 3 A4-страницы, XLS/XLSX — по 10;
проверены готовый PDF, предпросмотр и первая HISCOA/spool-страница без USB.
Теперь проба расширяется на отдельные листы и 1+3; окончательный HEAD требует
своей проверки. Это не поддержка Office в пользовательском интерфейсе.

Сборка/lint/JVM-тесты локально по-прежнему блокируются загрузкой Gradle;
результаты нового CI фиксируются в PR. Полная поддержка DOCX/DOC/XLS/XLSX,
выбор листов/Fit width, изоляция внешних ресурсов и аппаратная проверка
Canon LBP2900 остаются открытыми. Слияние и выпуск не выполнять.

Ранее работала страница PrintHand по сообщению владельца, но она не проверяет текущее обнаружение этого приложения.

Старый динамический получатель ATTACHED был ненадёжен; теперь используются наблюдение ключей списка каждые 2,5 секунды на видимом экране без повторной пробы неизменного списка и широковещательный DETACHED.

JVM проверяет детерминированные синтетические случаи, а не реальный CAPT.

- Следующая аппаратная проверка: после установки **подписанной** сборки, когда секрет настроен, оставить принтер включённым и прямой кабель подключённым; открыть диагностику, при нуле устройств один раз обновить/переподключить и отправить полный отчёт.
